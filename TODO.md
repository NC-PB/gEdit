## Bugs and risks

### NC correctness

- [ ] **Number classes, what is left**: there is no IS-A preset; the 0.001-count option of the Fanuc feed parameters is not modelled (inverse-time and per-tooth feeds get no value at all, which is the safe answer); a real conversion of a Sinumerik `G931` travel time belongs with M10's checks ([numbers.ts](src/lib/core/machines/numbers.ts), [syntax-fanuc §3.2](docs/planning/syntax/syntax-fanuc.md#32-numbers))
- [ ] **Tool-word variants, small gaps**: under the Okuma three-digit reading a six-digit word is not a tool change, and station names from the seven-digit form (`02`) and from `T2000` (`2`) are not normalised, so a file mixing both would split a tool in two (no real program does); under the Fanuc last-digit reading a short word `T1` is the station alone ([r6Variants.test.ts](src/lib/data/profiles/r6Variants.test.ts), [syntax-okuma §5.1](docs/planning/syntax/syntax-okuma.md#51-t-word))
- [ ] **The contradiction guard has no certain evidence for a Fanuc mill program read as Okuma** — their syntax is shared; the guard refuses only on `#` variables, a Fanuc lathe `P`/`Q` cycle, `G15 H`/`G16 H`, `G56 H` without `G43`/`G44`, or `SB=`. The gap is written down in [dialects.md](docs/user/dialects.md#which-dialect-a-file-gets) and waits for a manual of the Okuma machining-centre control (low priority) ([contradiction.ts](src/lib/core/profiles/contradiction.ts))
- [ ] **Okuma after M8, what is left**: a thread code on a `$` line does not protect the F above it (documented); one map item per line (`NEND M02` is listed as the end, not as the label `NEND`, by decision); program names are read up to 16 characters in the map and at the program start although the control takes that for subprograms only, by option (lenient, not wrong) ([syntax-okuma §11.7](docs/planning/syntax/syntax-okuma.md#117-after-m8-g10-review-what-the-okuma-profile-still-does-not-do))
- [ ] **Code-database gaps, what is left** (bug-fix round 1 filled the rest from the manuals): a Klartext cycle the database still lacks falls to the generic `CYCL DEF` (a `CYCL CALL` after it reads as "nothing defined", fail-safe) — cycle 20 (CONTOUR DATA: DEF-active, yet its `Q5` and `Q7` are tool-axis positions, so it needs a schema for "a DEF-active cycle whose parameters address arithmetic judges"), the pattern cycles 220/221, 233 and others; the tool-name parameters `QS13`/`QS18` of cycles 21, 22 and 25 are not parameters in the database, so address arithmetic refuses a cycle that writes them; Fanuc `G61.1` (a private program uses it, no manual here), lathe `G195`/`G241` (in neither manual; their blocks are "unknown code" to the checks, the extents and the arithmetic) and the lathe `G81`, which the manual has only in the Series 15 program format (a variant if your lathes run it); Okuma `G56 H` and `M54` in machining-centre programs (R9: the manuals at hand are lathe manuals), `G24`/`G25` as machine-position moves and `G314` (turret D); Sinumerik `FP=`, and a Scale Feed review of `CTOL=`, `OTOL=` and `FP=` (nothing reads them as feeds today; their labels say what they are); the labels of `G290`/`G291` and Fanuc `G15`/`G16` need a G10 look; `CYCLE82` lists the 9 arguments of the 2009 cycle manual plus the three mode arguments (anything after them refuses address arithmetic); `G65 A1.` with no `P` gets no "missing word" row on either Fanuc profile ([codes](src/lib/data/codes), [proposal R3](docs/planning/source-review-2026-09.md#r3-5-axis-and-high-speed-codes-and-words-that-are-data))
- [ ] **M10 data gaps, what is left** — Klartext and Sinumerik cycle depths (`Q201`, `DPR`) have no "relative to the tool-axis parameter" role, so the extents count them "not resolved"; a database arc flag would replace the geometry table of `extents.py` (the pole flag is done); subprogram calls are not followed by the extents; after a lathe `G90`/`G92`/`G94` box cycle the extents take the written end point as the position; Okuma arcs by radius `L` are not computed ([extents.py](src-tauri/resources/scripts/extents.py), [address_arithmetic.py](src-tauri/resources/scripts/address_arithmetic.py))
- [ ] **Small tokenizer/editing niceties left**: `_nc_modal.py` has no speed-vs-tool-change concept for Klartext's bare `TOOL CALL S…` forms; a block skip with indentation in front of it (`  /N120`) paints the indent as part of the skip mark (cosmetic)
- [ ] **Script texts, what is left**: the tool list drops values before an unnamed tool change and shows no `SB=` speeds (`S1=` is the main spindle's speed since M10); Scale Feed's `onlyAbove`/`onlyBelow` on a feed with no value in the limit unit is an open WP9.5a item ([tool_list.py](src-tauri/resources/scripts/tool_list.py))
- [ ] **Two-block lathe cycles, what is left** (`CodeParam.block` is built): the `G76` second-block `P` (thread height) is shown as written and never converted, because the readers of unit and position (`wordValue.paramOf`, `numbers.ts declaredUnit`) take the first declaration of an address; making them block-aware with `core/codes/blocks.ts` would let it be an increment; Edit Cycle refuses a two-block cycle, because a form writes one block ([blocks.ts](src/lib/core/codes/blocks.ts))
- [ ] **`I`, `J` and `K` after `G41.6`, `G42.6` and `G43.5` read as arc centres** (SK-04): in the blocks after the code they are the tool direction, but word lookup uses only the entry of the block's own code, so the inspector says "Arc centre"; it needs an "in force for word lookup" rule like the one for `G63` in `wordValue.ts`, for every dialect. - [ ] **Highlighting, the known differences from the tokens** (`src/lib/core/grammar`): six reasoned differences are listed as waivers in `differential.test.ts` (an Okuma function name before `[` is a keyword in the grammar and unknown in the tokens; Okuma local variables of at most four characters; a wrong-length Okuma `T` word left uncoloured; Sinumerik `CR15`, `L<n>` and `X[1]`); three or more stacked skip marks before a `DEF`, and a `DEF` name used on a later line, stay neutral.
