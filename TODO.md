## Bugs and risks

### NC correctness

- [ ] **Number classes**: a thread-pitch F counts as feed per revolution even under G94 (Okuma G181–G184, Fanuc mill G84/G74; 100× off on an Okuma 1 µm machine, so fix it before M9's extents); an Okuma 10 µm inch preset invents a 0.001 in unit; the Fanuc mill has no angular addresses (`C90000` reads as 9 in); per-tooth, inverse-time and G931 feeds have no class — wrong or missing values ([numbers.ts:265](src/lib/core/machines/numbers.ts#L265), [fanuc-gcode.json:42](src/lib/data/profiles/fanuc-gcode.json#L42))
- [ ] **Save As keeps the old dialect** (`a.nc` saved as `a.h` stays Fanuc) and backs up before noticing a read-only target — transforms run with the wrong dialect ([fileOps.ts:718](src/lib/app/fileOps.ts#L718-L744))
- [ ] **Remove Comments deletes Sinumerik's `;$PATH=` header** — the program loses its target folder ([removeComments.ts](src/lib/core/transforms/removeComments.ts))
- [ ] **Tokenizer gaps**: Sinumerik `LIMS[2]=`, `S[n]=`, `M[n]=`, `T[n]=` lose their address (read `NAME[expr]=` as one word in TS and Python); `1.5EX3` differs between grammar and tokenizers; an unclosed string or `[` runs to the line end (for `[` the comment mask disagrees) — hover, M11 and scripts misread values ([sinumerik.json:48](src/lib/data/profiles/sinumerik.json#L48), [tokenizer.ts:438](src/lib/core/nc/tokenizer.ts#L438-L446))
- [ ] **Sinumerik structure**: `:123` is a marker to the tokenizer but a block number to the grammar; renumber skips labels that start with N (`NEXT_PECK:` gets no number, `LAST_CUT:` does); the map lists `L10 (1)` as a call; `%NAME_MPF` is not recognized — renumber, search and the map disagree ([sinumerik.json:51](src/lib/data/profiles/sinumerik.json#L51), [renumber.ts:325](src/lib/core/transforms/renumber.ts#L325))
- [ ] **Okuma after M8**: a thread code on a `$` line does not protect the F above it (documented); LAP `E` feeds are never listed; one map item per line — a lead could be scaled ([syntax-okuma §11.7](docs/planning/syntax/syntax-okuma.md#117-after-m8-g10-review-what-the-okuma-profile-still-does-not-do))
- [ ] **Code-database gaps**: no Fanuc `G65` or Okuma `CALRG` entry; the Klartext `PLANE SPATIAL` words are not keywords (`PA+0` reads as a polar angle); `verify` works per code only, so unconfirmed CYCL DEF parameter orders show as confirmed; inserted cycles leave out Q395 — wrong hover and inserts ([types.ts:105](src/lib/core/codes/types.ts#L105-L107))
- [ ] **Modal data no G10 review has seen**: `cycle: cancel` on the CYCL DEF/CALL family, M89/M99 without `sets`, no feed unit on a plain Klartext F, `speedLimit` on the mill G92 — the Klartext modal state scripts see rests on it ([heidenhain.json:435](src/lib/data/codes/heidenhain.json#L435))
- [ ] **"Renumber now?" after Remove Empty Lines or Remove Comments renumbers only the selection** — on a partial run the rest of the program keeps its old numbers, so blocks can end up out of order or duplicated ([ncCleanup.ts:56](src/lib/contrib/ncCleanup.ts#L56))
- [ ] **Script texts**: the scale tooltips say rapid feeds and surface speeds are left alone (both are scaled); scale feed calls a G33/G331/G332 F a pitch; the tool list's "surface" tag has no unit and says "(G96)" on G961, drops values before an unnamed tool change and shows no `SB=`/`S1=` speeds; the scale-feed summary should name the machine (the owner's wish) — the reports mislead ([scale_feed.py:4](src-tauri/resources/scripts/scale_feed.py#L4), [tool_list.py](src-tauri/resources/scripts/tool_list.py))

### Data safety

- [ ] **Two tabs can own one file** (a symlink, `..`, or a mapped drive next to its UNC path) — the later save silently overwrites the earlier one ([documents.ts:30](src/lib/stores/documents.ts#L30-L46))
