## Bugs and risks

### NC correctness

- [ ] **Number classes**: a thread-pitch F counts as feed per revolution even under G94 (Okuma G181–G184, Fanuc mill G84/G74; 100× off on an Okuma 1 µm machine, so fix it before M9's extents); an Okuma 10 µm inch preset invents a 0.001 in unit; the Fanuc mill has no angular addresses (`C90000` reads as 9 in); per-tooth, inverse-time and G931 feeds have no class; the Fanuc presets read a point-less feed per revolution "as written", where a control without calculator input counts 0.01 mm/rev (a lathe `F25` would be 25 mm/rev instead of 0.25), and there is no IS-A preset; the `F` of Okuma `G101`–`G103` is per minute whatever the feed mode — wrong or missing values ([numbers.ts:265](src/lib/core/machines/numbers.ts#L265), [fanuc-gcode.json:42](src/lib/data/profiles/fanuc-gcode.json#L42), [syntax-fanuc §3.2](docs/planning/syntax/syntax-fanuc.md#32-numbers))

- [ ] **Save As keeps the old dialect** (`a.nc` saved as `a.h` stays Fanuc) and backs up before noticing a read-only target — transforms run with the wrong dialect ([fileOps.ts:718](src/lib/app/fileOps.ts#L718-L744))

- [ ] **Tokenizer gaps**: Sinumerik `LIMS[2]=`, `S[n]=`, `M[n]=`, `T[n]=` lose their address (read `NAME[expr]=` as one word in TS and Python); `1.5EX3` differs between grammar and tokenizers; an unclosed string or `[` runs to the line end (for `[` the comment mask disagrees); Fanuc macro functions and print commands split into address letters (`FIX[#2]` is an `X` word, `POPEN` five words); Okuma two-letter `=` words (`TL=`, `CL`, `CP=`) read as local variables and four-digit option M codes (`M1292`) are not codes; Klartext `TIP-TIP` and the other PLANE words are unknown; a block with several skip levels (`/1 /3`) reads the second as an operator and a number — hover, M11 and scripts misread values ([sinumerik.json:48](src/lib/data/profiles/sinumerik.json#L48), [tokenizer.ts:438](src/lib/core/nc/tokenizer.ts#L438-L446), [okuma.ts:79](src/lib/core/grammar/okuma.ts#L79))
